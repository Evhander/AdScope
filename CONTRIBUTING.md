# Contributing

Thanks for helping improve AdScope.

## General rules

1. Keep each change focused on one concrete problem.
2. Do not mix UI refactors with core audio behavior unless necessary.
3. When possible, test on a real device.
4. If reporting a bug, include device model, Android version, and Spotify version.
5. Explain clearly whether the issue happens on phone speaker, headphones, Bluetooth car audio, or another route.

## Detection reports

If you report a false positive or a missed ad, include the text generated by **Copy diagnostics**, removing anything you do not want to share.

Useful information:

- device model,
- Android version,
- Spotify language,
- output route,
- whether the app was using FULL MUTE or a non-zero ad volume,
- and what actually happened.

## Guardrails

- Do not add telemetry.
- Do not add Internet permission.
- Every volume modification must have a safe restore path.
- Keep ad detection separate from playback logic when possible.
- Do not break the validated 1.3.7 stable audio behavior without a strong reason.
